## Context

Issue `terrene-foundation/delegate-connectors#26` (owner-authored, 2026-06-03) directed consolidating
the Delegate connector-receipt protocol into ONE open CC BY 4.0 spec in this repo, positioned as an
EATP profile, executed open-first. The normative source (two-layer model, v2-core +4-field per-signer
chain, per-issuer head, §8.9 TOFU state machine, §8.9.9 residuals) lived in the PRIVATE enterprise
repo's `specs/delegate-receipt-model.md`. The cross-repo read was authorized + journaled in
`journal/0006` (`cross-repo-authorized: terrene-foundation/delegate-connectors-enterprise`); the file
was fetched read-only via `gh api` (that one file only).

## Decisions

1. **Authored `specs/delegate-receipt-two-layer.md`** (open, CC BY 4.0, DRAFT → freezes on owner
   approval). It consolidates: §1 two-layer model · §2 Layer 1 (cites frozen
   `canonical-signing-bytes.md`) · §3 Layer 2 (boundary only) · §4 residency-internal reconciliation ·
   §5 conformance split + type firewall · §6 v2-core +4-field chain (`seq`/`prev_receipt_hash`/
   `protocol_version`/`key_id`) + §6.1 vector shapes · §7 authority · §8.1–§8.10 safety clauses incl.
   the full §8.9 head/TOFU state machine (T1–T5, C1–C3), §8.9.9 residuals verbatim, §8.9.11 head
   vectors · §9 change control.

2. **EATP-profile positioning (§0).** Per #26's paired governance directive, the spec frames itself as
   a profile/binding of **EATP** (the offline-vs-residency two-tier verification = EATP's verification
   gradient) + **PACT** (the constraint envelope = PACT's Operating Envelope), normatively referencing
   them rather than re-deriving trust theory. NOT a new standalone standard.

3. **Four leak-classes stripped** (verified by mechanical grep — zero hits): (a) proprietary file:line
   (`eatp/src/ledger.rs:366`, `anchor_property.rs`, etc.); (b) provenance pointers (`kailash-rs#1203`,
   journals 0033–0039, spine handoff docs); (c) primitive NAMES (`M4` → "residency-internal witness
   anchor"; the Layer-2 ledger engine → "append-only hash-chained audit ledger (implementation-
   internal; behavioural conformance only)"); (d) enterprise framing ("enterprise Rust tier", "the
   spine", "spine-owned", "dc-enterprise"). Boundary test applied per clause: a clause entered the open
   spec IFF a standalone public-key-only verifier can act on it using only the receipt/head's signed
   bytes + the §8.9 state machine.

4. **Kept open-safe per #26's comment:** the §8.9 TOFU state machine in full; §8.9.9 residuals
   **verbatim, MUST-disclose** (no softening to SHOULD); §8.9.10 as a **generic** cross-artifact
   non-correlation property (external head confers zero confirmation advantage; domain-separated) with
   the `M4` name + salt-construction mechanics dropped. Vectors V2-1..16 / HV-1..6 specified as
   SHAPES ONLY (no byte strings, `spec-accuracy.md` Rule 1) — to be generated by THIS repo's reference
   (Python) encoder into `tests/fixtures/` after the v2 re-freeze (never citing any other repo's
   reproduction as source of truth).

5. **Integer-domain divergence reconciled toward the frozen value.** The open spec states
   `[-(2^53-1), 2^53-1]` (the authoritative `canonical-signing-bytes.md` §1.3 value) and flags the
   protocol-spec §11 prose drift (`[-(2^63-1), 2^64-1]`) as stale, to be reconciled in the v2
   re-freeze (§6 upstream sequencing). Owner-approved to scope THIS PR as the spec doc only; the
   `canonical-signing-bytes.md` v2 pre-image re-freeze + reference-encoder vector generation is tracked
   follow-on.

6. **Scope fence (owner-confirmed):** this delivers the open spec ONLY. Demoting the enterprise
   `delegate-receipt-model.md` (stripping "contract-authoritative", pointing it at this open spec) is a
   SEPARATE later step in the enterprise repo requiring its own cross-repo authorization (journal/0006
   explicitly does NOT cover any enterprise-repo write).

7. **Sibling-dependency leak — gold-standards-validator CRITICAL, owner-dispositioned Option A.** The
   open spec normatively binds readers to `canonical-signing-bytes.md` (MUST-conform), whose status
   header (line 4) named "the Rust `dc-enterprise` tier" — a leak-class-(d) hit on the open surface one
   hop from the new spec. Owner chose to scrub the one phrase in THIS PR: line 4 → "a second conforming
   implementation" + "cross-language (e.g. Python↔Rust)" (status-header prose only; the FROZEN §1–§6
   byte rules are untouched). The two milder findings ride F-v2-refreeze (below): `canonical-signing-
bytes.md:17–19` names the OPEN kailash SDK symbol `kailash.delegate.audit.content_signing_bytes`
   (open-SDK ref, not a private-repo leak — wire-shape-only cleanup deferred), and `conformance.md:12,18`
   carry `kailash-py#1182` + journal pointers (the new spec does not reference `conformance.md`).
   Reviewer (spec-quality) returned CLEAN/publish-ready; both reviewers' only blocking item was this
   sibling reference, now resolved.

  open-surface scrubs deferred from Decision 7 — `canonical-signing-bytes.md:17–19` (audit-event
  reference → wire-shape-only) + `conformance.md:12,18` (strip `kailash-py#1182` + journal pointers).
- **F-type-firewall (P0-08b implication):** our own host signer (P0-08b, `dispatch_signing.py`)
  currently produces kailash's `SignedActionEnvelope` / `AttestedReadReceipt` as the **Layer-1
  receipt** types — but the two-layer model (§5) names those the **Layer-2 audit** layer and requires
  Layer-1 and Layer-2 types be DISTINCT. When the v2 receipt surface lands, the Python implementation
  needs the §5 type-name-distinctness reconciliation (rename/namespace one side) under a deprecation
  cycle. Recorded here per owner's "fold a note into the journal" disposition; not open-spec content.
- **F-enterprise-demote:** the authority-inversion step (demote `delegate-receipt-model.md` to cite
  this open spec as authority) — separate enterprise-repo session + authorization.

## Consequences

- One open normative contract now exists; any implementation (including the enterprise tier) is a
  consumer (#26 AC5). P0-10a (the connector_builder factory) remains parked — `trust_primitives.py`
  uncommitted on `main`, NOT included in this spec PR (explicit-path staging).
- The private enterprise spec was read once (authorized), used to author, then the local copy deleted
  (no private content persisted on disk or in the repo).

## For Discussion

1. The boundary test ("public-key-only verifier acts on the receipt/head's own signed bytes") cleanly
   severed every clause — but §5's type firewall surfaced that our OWN P0-08b uses the audit-layer
   names for receipts. Does that mean the two-layer model was latent-violated in P0-08a/b, or is it
   benign until v2 (where the distinct v2 receipt type lands anyway)?
2. The spec lives in `specs/` (domain-truth) while v2-core is not yet shipped. Is a forward-specifying
   protocol STANDARD (like `canonical-signing-bytes.md`, which specifies "for a second implementation")
   correctly housed in `specs/`, or should an un-frozen protocol-version spec live in `02-plans/` until
   its vectors freeze — and does the DRAFT marker + shape-only vectors adequately satisfy
   `spec-accuracy.md` for a standard vs an implementation spec?
3. If the enterprise `delegate-receipt-model.md` later diverges from this open spec (e.g. a residency
   anchor detail), which is authoritative — and does the open spec need an explicit "implementations
   MUST NOT author a parallel normative spec; divergence is a defect against this document" clause
   beyond the §7 authority statement?
